# خريطة تطوير وتشغيل اللوحات الأربع — AIN SALAH EXPRESS

تاريخ المراجعة: 20 نوفمبر 2026

هذه الوثيقة تحدد وظائف التشغيل المستهدفة ومعايير القبول. وجود بند في الخطة لا يعني أن تكاملاً خارجياً غير منفذ أصبح متاحاً؛ يجب اعتماد كل وظيفة بعد اختبارها فعلياً.

## مبادئ مشتركة
- واجهة عربية RTL متجاوبة للهاتف والكمبيوتر، مع حالات تحميل وفراغ وخطأ واضحة.
- إظهار آخر تحديث للبيانات ومصدرها، وعدم وصف البيانات القديمة بأنها مباشرة.
- منع تكرار العمليات الحساسة باستخدام قيود قاعدة البيانات وعمليات ذرية.
- فصل الصلاحيات حسب الدور: admin وdriver وmerchant وcustomer، مع RLS على كل جدول خاص.
- رسائل نجاح/خطأ مؤقتة لا تحجب المحتوى، وسجل تدقيق للأعمال الإدارية الحساسة.
- عدم إظهار قسم المستحقات أو القيود المالية للمستخدمين؛ بناءً على قرار المنتج الحالي، لا تعرض واجهات مالية تشغيلية للسائق أو المطعم أو الزبون.
- دعم الوصول بلوحة المفاتيح، أحجام لمس مناسبة، وتباين مقروء.

## 1. لوحة الإدارة — مركز التحكم
### الوظائف
- مؤشرات الطلبات حسب الحالة، المتاجر النشطة، السائقين المتصلين، التذاكر المفتوحة، والتنبيهات التشغيلية.
- إدارة الطلبات: بحث برقم الطلب والهاتف والتاريخ والحالة، تفاصيل العناصر والعناوين، سجل الحالة، الإلغاء بسبب موثق، وإعادة الإسناد عند الحاجة.
- إدارة المتاجر: إنشاء الحساب والمتجر، تثبيت الموقع على الخريطة، تعديل ساعات العمل والتغطية والبيانات والصور والحالة.
- إدارة السائقين: مراجعة الطلبات والوثائق، اعتماد/رفض بسبب، حالة الاتصال، آخر إشارة GPS، وإيقاف مؤقت موثق.
- إدارة المنتجات والتصنيفات والقسائم والمخزون ومناطق التوصيل وسياسات الخدمة.
- إدارة العقود: قوالب حسب نوع الطرف، رقم مرجعي، إصدار ومسودة وتوقيع وإلغاء، معاينة وطباعة متعددة الصفحات، وملحقات مخصصة.
- الدعم: صندوق وارد للتذاكر، أولوية وتصنيف ومسؤول معالجة، ردود محفوظة، سجل كامل للمحادثة.
- سجل تدقيق للإجراءات الإدارية: الفاعل والوقت والكيان والقيمة السابقة والجديدة وسبب التعديل.
### ضوابط
- لا تسمح الواجهة وحدها بتجاوز RLS أو صلاحيات الخادم.
- العمليات الحساسة تتطلب تأكيداً وسبباً، وتُسجل في سجل التدقيق.
- لا تحذف سجلات الطلبات أو العقود التي لها أثر تشغيلي؛ استخدم الأرشفة والحالة.

## 2. لوحة السائق
- بطاقة حالة واضحة: غير متصل/متصل/في مهمة، مع زر واحد لتغيير الحالة.
- صندوق مهام بترتيب الأحدث والأقرب وفق بيانات موقع موثوقة، مع تفاصيل الاستلام والتسليم.
- قبول المهمة مرة واحدة فقط، ومنع التعيين المزدوج عبر قاعدة البيانات.
- خريطة واسعة مع علامات المطعم والسائق والزبون، وملاءمة تلقائية للنقاط، وتحديث Realtime/ GPS.
- إظهار وقت آخر GPS وعمر الإشارة، وإظهار حالة غير متصل عند تقادمها؛ لا تعرض نقطة قديمة كأنها مباشرة.
- خطوات الرحلة: قبول، وصول للمطعم، استلام، في الطريق، تسليم مع رمز تحقق إن فُعّل.
- سجل الرحلات، المساعدة، الإبلاغ عن مشكلة، والاتصال بالجهات ذات الصلة.
- حالة وثائق السائق والعقد وطلب تحديث الوثائق.
- لا تعرض مستحقات أو قيوداً مالية في لوحة السائق وفق قرار المنتج الحالي.
### حدود معلنة
تحديث GPS يتطلب إذن الموقع والإنترنت وتشغيل الصفحة. تتبع الخلفية الموثوق عندما يكون التطبيق مغلقاً يحتاج تطبيقاً أصلياً أو تكاملاً خلفياً مدروساً.

## 3. لوحة المطعم
- صندوق طلبات حي مع تنبيه الطلب الجديد، مؤقتات، وفرز حسب الحالة والعمر.
- قبول/رفض مع سبب، بدء التحضير، جاهز للاستلام، وملاحظات داخلية.
- قائمة المنتجات: إضافة وتعديل وأرشفة، صور، وصف ومكونات ومسببات حساسية، سعر، توافر ومخزون.
- ساعات العمل، الإغلاق المؤقت، وقت التحضير المتوقع، الحد الأدنى للطلب، ومعلومات الاتصال.
- صفحة معاينة كما يراها الزبون.
- مراجعات وتقييمات وشكاوى مع رد مهني.
- إدارة وثائق المطعم والعقد وتاريخ الانتهاء وطلب التجديد.
- لا تعرض مستحقات أو قيوداً مالية في لوحة المطعم وفق قرار المنتج الحالي.

## 4. لوحة الزبون
- استكشاف المتاجر والبحث والتصفية والتصنيفات والمفضلة.
- صفحات متجر ومنتج واضحة مع الخيارات والإضافات ومعلومات الحساسية عند توفرها.
- سلة مرتبطة بمتجر واحد، ملخص سعر واضح، وقسيمة صالحة ورسوم توصيل قبل التأكيد.
- عناوين محفوظة مع تحديد الخريطة والتحقق من الهاتف.
- متابعة مراحل الطلب وخريطة السائق فقط عند توفر إشارة حديثة.
- سجل الطلبات وإعادة الطلب وتقييم بعد التسليم.
- إلغاء الطلب فقط ضمن الحالات والسياسة المعتمدة.
- مركز دعم بتذاكر ورسائل خاصة بصاحب الحساب.

## الوثائق والعقود
- العقد الرئيسي، ملحق بيانات الأطراف، ملحق تجاري، ملحق نطاق الخدمة، وقائمة تحقق للوثائق.
- تحديد المدة والمقابل والعمولات والتجديد والإشعار والإنهاء بوضوح.
- بنود السلامة والجودة والسرية والبيانات والملكية الفكرية والشكاوى والمسؤولية والقوة القاهرة والقانون الواجب التطبيق.
- صفحات مستقلة للطباعة، ترقيم واضح، حقول توقيع وختم وتاريخ، وتذييل يوضح رقم العقد.
- لا تعتمد الصياغة قانونياً قبل مراجعة محامٍ جزائري وتعبئة بيانات الكيان القانوني والتراخيص والضرائب وملاحق كل نشاط.

## معايير قبول قبل الإطلاق
1. حساب اختبار لكل دور مع التحقق من عدم عبور البيانات بين الأدوار.
2. تنفيذ طلب كامل من إنشاء السلة حتى التسليم والتقييم.
3. محاولة قبول الطلب من سائقين بالتزامن والتأكد من فوز سائق واحد فقط.
4. اختبار GPS بإشارة حديثة ثم إيقافها والتأكد من تحول الحالة إلى قديم/غير متاح.
5. اختبار إنشاء متجر مع تثبيت الإحداثيات ثم إعادة تحميل الصفحة والتحقق من بقاء الموقع.
6. إنشاء عقد مطعم وسائق، معاينتهما وطباعتهما على الهاتف والكمبيوتر وفحص انقسام الصفحات.
7. فتح تذكرة من الزبون والرد من الإدارة والتحقق من الخصوصية.
8. تجربة انقطاع الشبكة وإعادة الاتصال وتكرار الضغط على الأزرار ومنع الطلبات المكررة.
9. مراجعة سجلات Supabase وVercel وأخطاء المتصفح.
10. تنفيذ تجربة ميدانية محدودة في عين صالح قبل الإطلاق العام.

## تكاملات غير مدعاة الاكتمال
- الدفع الإلكتروني غير مدمج.
- Web Push عند إغلاق التطبيق ليس ضماناً حالياً.
- مسافة الطريق الفعلية والتسعير على شبكة الطرق يحتاجان خدمة توجيه ذات سياسة استخدام موثوقة.
- OSRM العام وخريطة OSM العامة ليسا SLA إنتاجياً.
- لا تعتبر وحدات التاكسي أو نقل البضائع أو الحرفيين قابلة للحجز قبل تنفيذ تدفق مستقل واختباره.
